# 验证结果、证据身份与适用范围

## 如何使用验证证据

本页描述当前版本的验证范围、测量结果和复核方法。每份结果按其源码、数据、配置、窗口和场景身份解释；文档维护不会改变经济测量的来源。

收益率 `total_return` 与财富倍数不同，财富倍数为 `1 + total_return`。最大回撤以负数报告。实际成交记录与日期／股票／方向桶分别统计，后者不是券商订单数；各袖套独立成交、双边分别承担费用，不能虚构跨袖套净额。

## Pool A–J 研究验证边界

生产 17 股正式验收与新增研究股票池分开维护。`quantfusion/config/universe.py` 继续定义正式生产 17 股及其前缀；`quantfusion/config/research_universes.py` 定义 Pool A–J。研究股票池、2023 年起窗口或 `scripts.compare_universes` 产生的结果均为非 canonical 研究证据，不能覆盖下方 958 场景正式计划、黄金值、固定 seed、成本口径或发布回执。Pool 比较强制绑定完整 manifest 与逐文件 SHA-256；研究固定指数允许显式独立提供方回退。整个请求窗口早于已核验首个交易日的成员只能记为上市前 N/A，不能补造历史；报告另列逐成员实际首末观测日期。

Pool 研究回放复用 `ProductionReplayEngine`、现有交易费用、风险政策、固定信号参考和独立风险篮。数据准备须保留研究窗口前的真实预热历史；晚上市标的不补造上市前记录。由研究下载器生成的完整 manifest 逐文件绑定 SHA-256，中断时保持 `complete=false`、已完成标的和缺失列表；比较入口拒绝不完整 manifest、缺失固定风险输入、哈希漂移和明显陈旧数据。

两只固定路由指数是股票池比较的共同输入，不允许把指数缺失造成的现金路径解释为某个 Pool 的策略表现。比较前要求指数具有 MA120 所需的预热观测、窗口内相同日期覆盖和可接受的截止日新鲜度；报告保存指数 SHA-256。股票 manifest SHA-256、请求窗口、权益曲线实际观察窗口、股票代码与名称也随 JSON 报告保存。

比较报告至少包含累计收益、年化收益、最大回撤、实际成交记录、建模换手率、全现金日比例、平均现金比例、按实际成交和截至当日最后可见收盘价重建的持仓 HHI，以及风险事件类型和次数。请求窗口与实际观察窗口必须分别解释；观察区间明显短于请求区间属于输入／覆盖失败，不得标成完整历史结果。

本任务要求的 Pool B/F/G 2023 年起历史回放属于上述研究验证，不因工程测试通过自动成立。只有同一源码、完整实际输入、固定风险／指数证据和实际报告身份闭合后，才可描述对应研究运行结果；失败数据获取、部分工件和旧 SHA 结果均保留其真实状态，不能冒充当前 HEAD 验收。

## 正式发布与诊断边界

正式 CLI 默认候选标识为 `native-default`，直接使用默认策略配置。财富比较使用固定 incumbent，相同场景 ID、类型与有序股票池配对；原始参考保留独立诊断。两份参考均按完整内容核验，缺少或替换参考即失败关闭。

正式发布使用当前配置、完整计划和当前验收规则。显式研究候选标识只用于诊断选择。

当前验收覆盖固定 17 股科技主池、收盘信息决策及下一可交易开盘执行。主池含本金净财富至少保留固定 incumbent 的 99%，回撤不高于基准且不超过 18%，财富或回撤至少一项改善。prefix、leave-one-out、add-one、permutation 的最大回撤不超过 18%，配对财富最低值、P10、中位数分别至少为 65%、85%、100%。add-one 使用 5/9/13 股前缀。随机子池配对财富 P10、中位数分别至少为 85%、100%，回撤最大值、P90 和超过 18% 的数量均不劣于同场景基准。交易统计用于成本和操作负担分析。

验收定义见 `artifacts/diagnostics/no_waiver/production-primary/contract.json`。`native_joint_acceptance` 记录参考身份和验收结果；账户风险历史、实际成交与输入完整性同时接受校验。

使用 ID、family、ID 文件或 shard 筛选的压力任务都是诊断，只能写独立检查点与诊断 JSON，不能更新 canonical 工件。发布前 prefix 与 universe 的共同场景须逐条一致。读取当前正式基线时仍重算记录、门禁、发布评估与来源绑定；内部一致性不是数字签名，也不等于重新认证全部外部原始账本。

## 优化器验收协议

优化器按风险、换手、收益参数族研究，以收益、回撤与交易次数构造 Pareto 前沿，近似收益档优先低回撤与少交易。普通及压力 holdout 是推广门：财富至少保留基线 99%，回撤最多恶化 0.5 个百分点，交易最多增加 3%；只有财富至少提高 5% 时才允许突破交易限制。此协议不是日常买卖规则，不因发布版本而改变。

## 账户建议与治理观察

账户候选评分保留 15% 行业相对强度，比较 20／60 日细分画像均值与完整科技候选池均值。必要候选缺失、提供层标记陈旧或实际截止日不一致时，不能缩小横截面并用中性值继续推荐，而是抑制新增买入。可用持仓的成本保护、趋势退出和可卖数量提示仍独立保留。

账户快照的 `schema_version=3` 是输入数据协议，不是产品发行版本。账户、日期、金额、可卖数量、峰值和建仓证据均须真实合格。峰值证据不完整时披露 `PEAK_EVIDENCE_INCOMPLETE`，停用依赖该证据的保护；买入 `shares=0`，`indicative_target_shares` 仅为收盘估算。真实账户快照不进入历史回放，也不提供券商执行或跨日账本恢复。

治理模块读取状态形成预热健康、独立风险意见、袖套共识和覆盖置信度，不直接修改交易账本；应用层另行消费预热状态，`INVALID` 抑制新增买入，`DEGRADED` 本身只提示，`READY` 表示该健康检查通过。风险事件的 1／3／5／10／20 日结果和机会成本是事后分析，禁止回填为当时输入。边界与入口见 [README](../README.md) 和[诊断说明](DECISION_DIAGNOSTICS.md)。

## 数据、因果与执行限制

前复权数据可能因公司行动重述；科技股票池有幸存者及事后关注偏差，集中上涨窗口会放大收益。收盘生成信号，模拟成交最早在下一可交易日开盘；日线无法证明盘中路径、排队、冲击和全部特殊交易规则。跳空、连续跌停及流动性不足可能使损失超过保护线。

日扫默认指数目录为独立运行目录 `data_cache/regime`，冻结输入受写保护。模拟日扫和账户建议独立检查沪深交易日日历及应覆盖日；日历仅覆盖 2024–2026 年，必要指数缺少目标交易日即失败关闭，不能用自然日容忍绕过。股票缺失处理按入口区分，详见[数据说明](../data/README.md)。

Pool 历史比较不使用日扫有限日历推断长期交易日，而是读取实际股票和固定指数日线；因此它另外核验固定指数预热、窗口内同步覆盖、截止日新鲜度，以及股票研究 manifest／哈希。该差异只属于研究输入验证，不放宽日扫的独立交易日要求。

## 工件与工程验证

市场数据、黄金预期、冻结机器证据及其来源标识保持字节身份；协议修订号、依赖版本和源码指纹不属于产品发行版本。冻结治理合同通过不可变 Git 对象验证原始哈希，不在当前文档中发布执行日记。`artifacts/validation/candidates/` 和 `artifacts/diagnostics/` 保留可追溯的失败及研究证据，不能作为当前使用指南或新任务授权。

先验证受影响范围，再按实际影响扩大；不为纯文档重新搜索参数或重算正式经济矩阵。测试结果须绑定真实提交 SHA，未运行或未核验项不能写成通过。工程通过、来源绑定的经济接受、实际交易可执行性分别判断；均不保证未来收益。

发布复核包含登记的跨窗口及正常／不利成本主池配对结果。各主池对照的历史回撤不超过 18%，财富下降时须伴随回撤改善。跨窗口结果使用已查看数据；股票池扰动与跨市场验证分别解释。
