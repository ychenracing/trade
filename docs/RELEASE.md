# Quant Fusion 1.0.3 发布说明

## 产品定位

Quant Fusion 是面向 A 股科技、算力硬件、光通信和半导体产业链的日线量化研究与人工决策支持系统。`main` 是唯一维护入口，产品版本为 `1.0.3`，版本标签固定对应发布源码提交。它不连接券商、不自动下单、不托管账户，也不保证未来收益。

## 相比 1.0.2 的主要变化

`1.0.3` 在 `1.0.2` 基础上，收口普通路径账户风险预算（ordinary-AB5）的持仓减仓推迟规则，并刷新受影响的冻结黄金回归。固定 17 股生产池、既定风险阈值中的硬路径、交易费用、收盘后决策到下一可交易日执行边界保持不变；固定 incumbent 比较基准身份未改写。正式 958 场景已在发布源码 `9ff459d52c3daede7902a04b8861bc35eac53f92` 上重新跑通并晋升 `economic_acceptance=MET`。

### 普通路径持仓减仓推迟

在保留策略有效持仓时，普通路径仅在同时满足以下条件时推迟按比例持仓减仓：

- 相对毛敞口上限的超出不重大；
- 剩余损失预算充裕；
- `equity / peak ≤ 0.9245`。

预警、冲击及其他硬路径的减仓与退出不受影响，买入 envelope 语义保持不变。

### 经济与研究证据（相对 1.0.2）

- **common-5 经济改善。** 同一冻结窗口与成本口径下，五股池累计收益由约 `7.9845` 提高到约 `9.3517`（财富倍数约 `8.98` → `10.35`），普通路径持仓减仓次数与袖套成交负担下降；回撤未恶化。
- **Core17 相对 1.0.2 不变。** 固定 17 股生产主池的收益、回撤、成交与事件指纹与 `1.0.2` 一致（财富倍数仍为 `9.610543`，最大回撤 `-15.104978%`）。
- **研究股票池净正向。** Pool E/F/H/I 等研究池相对 `1.0.2` 基线改善，其余可测研究池持平；未发现可测池净恶化。证据属于指定研究池与窗口，不代表未来收益保证。
- **不是 archive 对齐。** 本版只吸收普通路径耐心减仓的可移植规则，不以 archive 分支的成交路径、剪裁强度或完整经济结果为目标，也不宣称与 archive 业绩对等。
- **正式 958 经济验收为 `MET`。** 已在发布源码 `9ff459d52c3daede7902a04b8861bc35eac53f92` 上以 `native-default` 跑通完整 958 场景；`acceptance=accepted`、`canonical=true`，发布回执为 `ECONOMICS_AND_QUALIFICATION_MET`。Core17 财富倍数 `9.610543`、最大回撤 `-15.104978%`；固定 incumbent 比较基准保持不变。完整证据见[验证说明](VALIDATION.md#formal-stress-evidence)。

### 相对 1.0.2 未改变

- 固定 17 股生产股票池成员与生产日扫入口；
- 预警、冲击等硬风险路径，以及账户风险预算中的买入 envelope；
- 交易费用、滑点、T+1、涨跌停、整手和成交容量模型；
- 正式 958 场景计划、seed 与固定 incumbent 比较基准身份；当前发布回执已绑定本版源码；
- 不连接券商、不自动下单、只提供人工决策支持的产品边界。

## 量化特性

**多策略趋势参与。** 唐奇安突破、双均线趋势与 ATR 通道各自保存信号、持仓和成交轨迹；快、中、慢三个袖套分配资金，状态变化后的动态分配只迁移未使用现金，不把多个策略简单当成投票，也不虚构跨袖套订单净额。

**市场状态与弱市路径。** 内部趋势、过渡、震荡状态结合外部固定指数的中期趋势及连续确认；路由切换沿用持续账户。已有趋势账本由相应风险执行者处理，空仓进入弱市才启用合格正动量龙头路径；成熟与新兴候选、周期内名单冻结用于约束追逐短期排名。新兴龙头位置继续使用时点可见的风险调整动量、相对强度、突破位置与成交量确认改进候选质量。

**账户与持仓两级风险。** 默认启用账户风险预算，依据持续权益高水位、剩余预算、规划压力和退出成本裁剪新增敞口或生成减仓计划；普通路径在超出不重大、剩余预算充裕且 `equity / peak ≤ 0.9245` 时可推迟按比例持仓减仓，预警与冲击等硬路径不推迟。未成交卖单不增加买入额度。持仓层结合成本、ATR、盈利回吐、灾变和趋势健康证据，保护线有明确的独立启用条件；锁定、冷却和恢复确认保留各自职责。

**行业结构与组合约束。** 细分行业画像及向父画像的参数收缩，配合单股／总仓位上限、行业集中度、候选确认、独立风险篮与成交容量校验。三类策略共用规范撮合、费用和核算，不为研究报告另建交易引擎。

**面向真实使用的日扫。** 模拟扫描与真实账户建议分开：模拟持仓不冒充真实持仓，真实快照也不注入历史回放。严格账户输入、峰值证据、指数交易日覆盖、预热健康与实际预算回执控制是否可发布正常建议。中文报告展示支持买卖的信号、阻止原因、数量、数据日期及最终处理，并绑定来源 JSON 哈希。

**可追溯研究。** 冻结数据、来源指纹、精确事件回归和 958 场景正式计划覆盖前缀、留一、逐一加入、随机子集与顺序置换；诊断结果与正式发布隔离。离线建议评价使用实际保存的建议及明确因果日期，事后收益不回填为当时信号。

**多股票池历史研究。** 生产日扫仍使用原 17 股主池；研究层另提供 Pool A–J，不需要修改策略源码即可切换光通信、半导体及完整科技产业链组合。研究回放默认起点为 `2023-01-01`，也可显式指定起止日期。研究股票数据写入独立缓存，并继续加载既有固定指数参考和独立风险篮；新增研究标的复用已有行业画像、路由和风险规则，不修改原参数。

## 实用优势

优势在于把信号、组合、风险、数据和执行约束放在可以核验的同一调用链内，而不是只展示回测收益。费用、滑点、T+1、涨跌停、手数及成交量容量进入模拟；收盘到下一可交易开盘的因果边界明确。多层限制及失败关闭有助于识别不具备行动条件的情形，但不能消除市场风险。

单进程模块化结构、统一实现入口、独立运行缓存和来源绑定报告适合个人维护及人工复核。固定基线、股票池扩展与顺序扰动检验有助于暴露路径敏感性，不代表已经证明任意股票池或未来市场的泛化优势。

## 多股票池研究入口

Pool A–J 的名称和代码映射集中在 `quantfusion/config/research_universes.py`。旧的生产 17 股 `SYMBOL_NAMES` 不因研究池扩展而改变。单池趋势回测可直接使用 `--pool`；`backtest_cli` 日期参数统一为 `--start-date/--end-date`。Pool B/F/G 或其他多池比较使用同一 `ProductionReplayEngine` 连续账户路由，不复制交易信号、费用、风险或执行实现。

研究数据应放在独立目录。以下命令准备 Pool B/F/G 的股票、固定信号参考和现有独立风险篮；未指定 `--output` 时，下载器默认使用 `data_cache/research_market`，不会覆盖仓库冻结 `data/market`。下载器会在回放窗口前额外保留 365 个自然日的真实行情用于 warm 指标预热，但收益、回撤和报告窗口仍从指定的 `--start-date` 开始。`YYYY-MM-DD` 应替换为已经完成收盘且数据可获得的截止日。

```bash
python -m scripts.download_market_data \
  --pool pool_b --pool pool_f --pool pool_g \
  --start-date 2023-01-01 --end-date YYYY-MM-DD \
  --output ../trade-runtime/research-market

python -m scripts.compare_universes \
  --pool pool_b --pool pool_f --pool pool_g \
  --start-date 2023-01-01 --end-date YYYY-MM-DD \
  --data-dir ../trade-runtime/research-market \
  --regime-data-dir ../trade-runtime/regime \
  --output-dir ../trade-runtime/universe-comparison
```

Pool 数据准备复用现有 Eastmoney→Sina→Tencent 提供方切换，并保留旧无 Pool 的 Eastmoney-only 冻结快照默认行为。研究下载开始前即写 `complete=false` manifest；单股 CSV 原子替换并记录提供方、首尾日期、行数和 SHA-256，只有全部所需股票完成后才切换为 `complete=true`。中途失败或硬中断不会把部分目录冒充完整研究输入。对明显陈旧数据和 Tencent 1000 行上限造成的长历史截断失败关闭。

比较运行前要求所选 Pool、固定信号参考、现有 `RISK_BASKET` 与两只固定指数证据完整。完整研究 manifest 会逐文件复核 SHA-256；股票侧必须具有可接受的截止日覆盖。两只固定指数必须有 MA120 所需的预热观测、窗口内完全一致的日期序列和可接受的截止日新鲜度。固定风险或指数证据不足不会被解释成股票池自身的现金防御表现。

比较输出同时保存 JSON、CSV 和 Markdown，包含股票数量和成员名称、请求窗口、实际观察窗口、累计／年化收益、最大回撤、成交记录数、建模换手率、空仓比例、平均现金比例、依据实际成交与截至各组合日最后可见收盘价重建的持仓 HHI，以及风险事件类型和次数。JSON 还保存股票 manifest SHA-256 与两只固定指数 SHA-256。该报告是研究输出，不改变生产交易决策，也不是新的策略晋级门。

研究窗口支持从 `2023-01-01` 开始，不代表仓库旧冻结样本已经覆盖 2023。现有 `data/market` 的发布清单主要从 2024 年开始，原 17 股正式经济证据仍绑定 2025-04-01 至 2026-07-20。较晚上市标的在上市前没有观测，不补造历史；只有真实数据出现后才参与回放。历史比较必须保存实际数据来源、窗口、源码和报告身份，不能用旧 SHA 或旧冻结业绩证明新窗口。

`688825` 和 `688037` 在研究 symbol catalog 中分别按当前证券身份解析为长鑫科技和芯源微；旧参数画像文件中的细分类别用于复用既有参数工厂，不作为证券名称事实源。证券名称以研究 catalog 为准，避免把历史注释误当作 symbol mapping。

## 证据与风险限制

冻结黄金回归已绑定当前 ordinary-AB5 持仓减仓推迟机制；Core17 与 `1.0.2` 一致，common-5 与部分研究池改善。正式 958 已在本版源码上验收通过（`economic_acceptance=MET`），deployment-release 与发布回执绑定 `9ff459d52c3daede7902a04b8861bc35eac53f92`；固定 incumbent 比较基准未改写。完整正式证据入口见[验证说明](VALIDATION.md#formal-stress-evidence)。

风险预算存在机会成本，不能宣称所有行情收益改善。科技集中样本、幸存者偏差、前复权重述、数据覆盖范围、跳空、连续跌停及人工执行误差仍需独立考虑。日历证据仅覆盖 2024–2026 年；缺少合格输入不能靠忽略错误继续。真实账户仍需使用者维护准确快照和权益高水位；报告不是券商订单或自动交易授权。

Pool A–J 的比较结果属于新增研究证据，不能覆盖上述固定 17 股正式验收边界。请求窗口与实际观察窗口、股票／指数输入哈希、源码身份和报告身份均应匹配后才可比较；失败、缺失或输入不完整必须保留，不能通过删股、缩短窗口、改风险参数或重写旧黄金结果隐藏。

## 运行入口

在仓库根目录安装运行依赖，按 `README.md` 与 `data/README.md` 准备独立运行目录及真实输入。先检查公开参数：

```bash
python -m quantfusion.application.daily_scan --help
python -m quantfusion.application.backtest_cli --help
python -m scripts.compare_universes --help
python -m scripts.decision_diagnostics --help
```

日常命令、严格账户数据协议、故障排查和全部当前参数以 `README.md`、各入口解析器与 `quantfusion/config/` 为准。依赖版本、账户数据协议和不可变证据标识不是产品发行版本，不随 `1.0.0` 标签重写。
