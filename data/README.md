# 冻结行情与日常运行数据

本目录保存可复现回测的只读行情证据，不是日常更新目录。`market/` 服务于冻结趋势回归，`regime/` 服务于外层路由和历史弱市验证；缓存与近期日扫指数必须放在独立运行目录。完整操作入口见[使用说明](../README.md)。

## 冻结目录与来源

- `market/`：当前 17 只交易股票所需的冻结前复权日线，以及供历史研究审计的其他样本、`manifest.json` 与 `SHA256SUMS`。
- `regime/`：16 只验证股票的历史前复权日线、两个非交易指数、`MANIFEST.json` 与 `SHA256SUMS`。
- `regime/000300.csv` 和 `regime/000682.csv` 只提供指数路由证据，不进入股票交易池。该冻结清单中两个指数均截至 **2026-07-28**，不能冒充任意目标交易日的最新输入。

历史股票前缀来自已审计的东方财富和腾讯验证快照。两组股票数据重叠的 2024 年以后区间以 `market/` 为生产基准；拼接差异和来源特定的成交量比例记录在 `regime/MANIFEST.json`，包括 `688256` 的处理。股票价格为前复权、成交量统一为股；指数清单声明 `index_adjustment=unadjusted`，不能把股票前复权或成交量换算结论套用到指数。

在仓库根目录执行只读完整性检查；两个子命令各自在独立目录执行：

```bash
(cd data/market && sha256sum -c SHA256SUMS)
(cd data/regime && sha256sum -c SHA256SUMS)
```

以上为提供 `sha256sum` 的 shell 示例，不会下载或更新文件。`scripts/run_regime_validation.py` 在经济验证结果中另记录哈希、首尾日期和行数，但它是验证运行，不是日常数据修复命令。仅为检查文档或文件哈希不需要运行它。

## 日常指数准备与刷新边界

通过现有日扫参数 `--regime-data-dir` 指向独立目录，例如 `../trade-runtime/regime`；股票缓存和结果也放在独立的 `../trade-runtime/cache` 与输出目录。显式目录按普通路径处理，不因名称自动映射到冻结目录。

当前模拟日扫和账户建议都会调用 `quantfusion/data/contracts.py` 的 `refresh_regime_indices`。目标日期距运行机器当天不超过过去两个自然日时，会尝试通过 AKShare 的 `stock_zh_index_daily_em` 获取 `csi000300`、`csi000682`，并分别写入 `000300.csv`、`000682.csv`。这是现有扫描流程的一部分，没有独立的指数下载 CLI。较早的历史目标不会联网补指数，只检查文件是否存在；需要使用者事先准备覆盖目标与预热区间的合法文件。

正常刷新保存每个指数的状态、末日和行数到 `live_refresh_manifest.json`。单个指数刷新失败时可能保留其旧文件；两只指数不是整体原子更新。这个状态文件不是哈希认证或完整性保证，`updated` 也不代表已经满足路由预热与确认条件。没有 AKShare、网络不可用或历史输入缺失时，不编造日期或手工伪造成功状态。

**实现边界：**日扫的默认指数目录仍为冻结 `data/regime`，近期刷新并没有替它提供只读保护，因此日常命令必须显式传入独立目录。另一个独立边界是 `boundary_route` 返回最后一个可用指数日的状态；两个指数同时陈旧时，不能仅凭路由名称断言已按请求日失败关闭。实际使用前必须核对两个文件的真实最后交易日、覆盖和来源；不充分时不要把输出用于当前买入判断。这些说明不表示相关默认值或路由实现已被修复。

## 文件格式、单位与完整性

读取器为 `quantfusion/data/providers.py`，指数刷新规范化为 `quantfusion/data/contracts.py`，路由读取与状态机分别在 `quantfusion/regime/evidence.py` 和 `quantfusion/regime/state_machine.py`。人工准备文件时使用 UTF-8 CSV、六位代码文件名，推荐列为：

```text
date,open,high,low,close,volume
```

日期使用 `YYYY-MM-DD`，每个交易日一条真实观测；OHLC 为正的有限数，最高价不低于开收盘价，最低价不高于开收盘价，最高价不低于最低价。日期不能重复；读取器不会靠文件名推断正确标的、来源、单位或应有交易日。不得伪造缺失交易日、复制未来值或覆盖冻结 CSV。

股票 `volume` 的契约单位是股，不是手；在线股票提供方按其单位进行换算，已有缓存还需其真实生成的 `.csv.meta.json` 单位声明。不要仅为通过检查而给旧缓存补一份声明。指数刷新当前保留提供方数值，未执行股票提供方的手转股流程；指数不参与股票成交容量计算，不能把其成交量当作某只股票的可成交股数。通用读取器允许缺少成交量并补零，这只是格式兼容，不证明有流动性；人工文件应提供真实非负有限成交量并核实来源口径。

指数刷新器的 60 行检查、`detect_regime` 的 MA20/MA60 证据与当前 MA60/MA120 路由不是同一个就绪条件。路由在索引位置达到 120 后才评价均线，亦即每个指数至少有 121 条有效观测，还需要持续状态与确认历史；两个指数在所评价的交易日都须有数据。保留足够的真实历史，不把“121 行”当作立即可以买入的保证。

局部证据读取还使用 `MAX_EVIDENCE_STALENESS_DAYS=10` 的自然日容忍，但这既不保证所有路由分支都会核对请求日，也不表示滞后十天的数据适合当天决策。使用者负责核对目标交易日、实际截止日期、来源和可用交易日覆盖；不要放宽容忍或使用 `--allow-stale` 代替合格输入。

## 缺失和不足历史的适用范围

| 入口 | 当前处理与限制 |
|---|---|
| 弱市内部选股 | `select_positive_momentum_leaders` 对缺失、陈旧或不足 61 条观测的标的跳过；成熟通道另需 241 条价格观测及正的 240 日动量，新兴通道使用较短历史与独立条件。未入选不等于数据不可用。 |
| 显式研究过滤 | `RegimeAdaptiveBacktestEngine.run(..., allow_unavailable_symbols=True)` 可在适用分支过滤没有可观察本地数据的标的；这不是普通 CLI 的默认值，也不证明剩余股票的全部指标已就绪。 |
| 默认自适应回放 | `allow_unavailable_symbols=False`；`auto/replay` 发现请求股票缺少可观察数据时抛错，不静默缩小股票池。随后真实回放仍执行其数据和映射校验。 |
| 模拟日扫 | 预期可交易股票获取失败、提供层标记陈旧或实际截止日不一致时，正常路径中止；预热 `NOT_READY`、状态身份不匹配等可输出受限结果并抑制买入，不能叫作完整正常信号。 |
| 真实账户建议 | 所需候选、参考或持仓数据缺失、陈旧、证据不一致时按实际 `data_complete`、`valuation_complete` 与买入限制处理；可用持仓的防御建议仍可能保留，缺少估值的持仓标记 `DATA_ERROR`。不能把缺失持仓当成零持仓。 |

`regime/` 没有 2021 年股票历史，会限制较早窗口的成熟动量证据；这不等于现行所有弱市入口在整个 2022 年都必然空仓。晚上市股票保留真实上市边界，不补造上市前历史。

公共前复权历史可能在公司行动后重述。现存冻结证据保持原字节、清单及来源；日常运行数据独立更新，不因此成为新的正式基线。新的研究输入及验收须按有效合同建立独立身份，不能通过刷新冻结目录或黄金预期消除失败。
