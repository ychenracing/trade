# 冻结行情与日常运行数据

本目录保存可复现回测的只读行情证据，不是日常更新目录。`market/` 服务于冻结趋势回归，`regime/` 服务于外层路由和历史弱市验证；缓存与近期日扫指数必须放在独立运行目录。完整操作入口见[使用说明](../README.md)，只读评分、风险与建议评估见[决策诊断](../docs/DECISION_DIAGNOSTICS.md)。

## 冻结目录与来源

- `market/`：当前 17 只交易股票及池外信号参考所需的冻结前复权日线，以及供历史研究审计的其他样本、`manifest.json` 与 `SHA256SUMS`。
- `regime/`：16 只验证股票的历史前复权日线、两个非交易指数、`MANIFEST.json` 与 `SHA256SUMS`。
- `regime/000300.csv` 和 `regime/000682.csv` 只提供指数路由证据，不进入股票交易池。该冻结清单中两个指数均截至 **2026-07-28**，不能冒充任意目标交易日的最新输入。

历史股票前缀来自已审计的东方财富和腾讯验证快照。两组股票数据重叠的 2024 年以后区间以 `market/` 为生产基准；拼接差异和来源特定的成交量比例记录在 `regime/MANIFEST.json`，包括 `688256` 的处理。股票价格为前复权、成交量统一为股；指数清单声明 `index_adjustment=unadjusted`，不能把股票前复权或成交量换算结论套用到指数。

在仓库根目录执行只读完整性检查；两个子命令各自在独立目录执行：

```bash
(cd data/market && sha256sum -c SHA256SUMS)
(cd data/regime && sha256sum -c SHA256SUMS)
```

以上为提供 `sha256sum` 的 shell 示例，不会下载或更新文件。`scripts/run_regime_validation.py` 在经济验证结果中另记录哈希、首尾日期和行数，但它是验证运行，不是日常数据修复命令。仅为检查文档或文件哈希不需要运行它。

## 交易日与完整日线

模拟日扫和账户建议使用 `quantfusion/data/sessions.py`，默认日历为 `data/trading_calendar.json`，也可用 `--calendar-file` 指定已审查的独立输入。默认文件保存沪深交易所公告来源及 **2024-01-01 至 2026-12-31** 的有限覆盖范围；周末和公告休市日不开市，调休工作周末也不开市。它不是永久日历服务，不从股票或指数共同末日推断开市日。

输出 `scan_dates` 区分请求日 `requested_as_of`、应覆盖的最近完整交易日 `required_evidence_date`、下一可交易日 `next_trading_date`，实际行情日期另记在 `actual_evidence_dates` 或账户行情证据中。日历身份进入新快照；旧工件不会被补盖新认证。日历范围外、下一交易日不能确定、来源或结构不能核验时失败关闭，不外推 2027 年，也不将未知日当作周末。

市场时间为 `Asia/Shanghai`，不是设备时区。请求当日时，完整日线就绪边界采用上海时间 15:30；边界前明确提示“当日收盘数据未就绪”，不退回昨天伪称完成今天。达到时间边界仍必须收到目标交易日的有效日线，不能把时钟当作数据已更新的证明。历史扫描按显式历史截止日核验，不要求历史输入覆盖今天。

每只必需股票、只读参考股和两只固定指数都必须覆盖目标交易日。即使只落后一根日线且不足十个自然日，或全池与指数同时陈旧，也不能相互证明新鲜。提供方 `_stale`、缺失、未来观测、无效指数、目标交易日落后、未知日历分别保留原因；`--allow-stale` 不覆盖这些门禁。无法区分停牌与数据缺失时不补前值，不静默删股。

原有 `MAX_EVIDENCE_STALENESS_DAYS=10` 自然日检查继续执行其原有职责，不因日历收紧而放宽。覆盖交易日并不取代预热、账户估值、风险锁和其他数据校验。这是有意收紧的输入行为，不是策略阈值或评分调整。

## 日常指数准备与刷新边界

日扫默认指数目录为相对当前工作目录的 `data_cache/regime`，不再使用仓库冻结目录。建议通过现有参数 `--regime-data-dir` 显式指定独立目录，例如 `../trade-runtime/regime`；股票缓存和结果也放在独立的 `../trade-runtime/cache` 与输出目录。`--cache-dir` 与 `--regime-data-dir` 是独立参数，修改股票缓存目录不会自动修改指数目录。显式目录按普通路径处理，不因名称自动映射到冻结目录。

当前模拟日扫和账户建议都会调用 `quantfusion/data/contracts.py` 的 `refresh_regime_indices`。目标日期距运行机器当天不超过过去两个自然日时，会尝试通过 AKShare 的 `stock_zh_index_daily_em` 获取 `csi000300`、`csi000682`，并分别写入 `000300.csv`、`000682.csv`。这是现有扫描流程的一部分，没有独立的指数下载 CLI。较早的历史目标不会联网补指数，需要事先准备覆盖目标与预热区间的合法文件；日扫随后仍执行目标交易日校验。

仓库冻结 `data/market`、`data/regime` 及已发布日扫快照的子目录受写保护，路径解析后的同一目录也适用。指数刷新在这些目录只返回 `frozen_read_only` 或缺失状态，不联网、不写文件；将它们作为可写股票缓存会直接报错。历史回测继续通过 `data_dir` 只读加载。写保护不补齐缺失或陈旧数据，也不让旧证据自动成为当天合格输入。

正常刷新保存每个指数的状态、末日和行数到 `live_refresh_manifest.json`。单个指数刷新失败时可能保留其旧文件；两只指数不是整体原子更新。这个状态文件不是哈希认证或完整性保证，`updated` 也不代表已经满足目标交易日、路由预热与确认条件。没有 AKShare、网络不可用或历史输入缺失时，不编造日期或手工伪造成功状态。

`boundary_route` 返回最后一个可用指数日的状态；消费它的 `decide_current` 同时检查既有 `detect_regime` 结果，证据为 `unknown` 时返回现金防御。日扫传递请求的 `end_date`，不通过退回股票缓存末日掩盖陈旧证据；入口另行校验独立日历目标。底层路由函数的自然日容忍不是绕过入口覆盖要求的授权。

## 股票缓存与日扫冻结快照

股票缓存必须声明股数成交量契约；无法解析为正确对象的元数据不能作为有效契约。请求需要更早预热历史时，读取器重新查询完整区间，而非静默返回较短缓存；元数据记录已查询的起点，避免把真实上市前无数据误认为需要反复补齐。缓存 CSV 和元数据分别使用临时文件、刷盘和原子替换，二者并非整体事务。提供层的周末尾段查询优化只减少无效请求，不能替代日扫入口的交易所日历认证；提供方陈旧标记仍被拒绝。

模拟日扫先获取并校验交易池与 `PortfolioPolicy.regime_symbols` 的去重并集。当前完整输入包含 17 只交易股票和池外参考股 `688008`，因此股票快照含 18 个 CSV；参考股不进入交易候选、逐股报告或风险状态身份。缺失或为空的必需行情必须中止，不允许缩小股票池或缺失参考篮子。

`scripts/download_eastmoney_qfq.py` 默认同样下载交易池与固定参考篮子的去重并集；显式 `--symbol` 仍只下载指定标的。下载新研究数据须显式指定独立 `--output`，不得覆盖仓库冻结证据。

快照直接序列化已经校验的数据帧，不重新复制可能变化的股票缓存。清单必须覆盖全部声明股票和两只固定指数，逐一核验文件、哈希与长度；不完整或重复的清单不能仅凭自洽哈希通过。同日重跑只复用通过当前身份、覆盖和完整性校验的旧快照，保留原字节；不混用新日期与旧价格，不改写旧清单以适配新日历。

已经生成的不完整快照不会自动补写。应保留旧快照和风险状态；独立复现可选择新的 `--output-dir`，但新目录不会自动继承旧风险状态。不得删除状态或改写冻结证据来消除错误。`--reset-risk-state` 仅用于明确建立新的模拟研究身份；旧状态直到数据、回放和结果写入成功后才原子替换，输入失败不会先删除原文件。它不能解除真实账户风险锁。

## 文件格式、单位与完整性

读取器为 `quantfusion/data/providers.py`，指数刷新规范化为 `quantfusion/data/contracts.py`，路由读取与状态机分别在 `quantfusion/regime/evidence.py` 和 `quantfusion/regime/state_machine.py`。人工准备文件时使用 UTF-8 CSV、六位代码文件名，推荐列为：

```text
date,open,high,low,close,volume
```

日期使用 `YYYY-MM-DD`，每个交易日一条真实观测；OHLC 为正的有限数，最高价不低于开收盘价，最低价不高于开收盘价，最高价不低于最低价。日期不能重复；读取器不会靠文件名推断正确标的、来源、单位或应有交易日。不得伪造缺失交易日、复制未来值或覆盖冻结 CSV。

股票 `volume` 的契约单位是股，不是手；在线股票提供方按其单位进行换算，已有缓存还需其真实生成的 `.csv.meta.json` 单位声明。不要仅为通过检查而给旧缓存补一份声明。指数刷新当前保留提供方数值，未执行股票提供方的手转股流程；指数不参与股票成交容量计算，不能把其成交量当作某只股票的可成交股数。股票和指数都拒绝无穷价格或成交量。通用读取器允许缺少成交量并补零，这只是格式兼容，不证明有流动性；人工文件应提供真实非负有限成交量并核实来源口径。

指数刷新器的 60 行检查、`detect_regime` 的 MA20/MA60 证据与当前 MA60/MA120 路由不是同一个就绪条件。路由在索引位置达到 120 后才评价均线，亦即每个指数至少有 121 条有效观测，还需要持续状态与确认历史；两个指数在所评价的交易日都须有数据。保留足够的真实历史，不把“121 行”当作立即可以买入的保证。

## 缺失和不足历史的适用范围

| 入口 | 当前处理与限制 |
|---|---|
| 弱市内部选股 | `select_positive_momentum_leaders` 对缺失、陈旧或不足 61 条观测的标的跳过；成熟通道另需 241 条价格观测及正的 240 日动量，新兴通道使用较短历史与独立条件。未入选不等于数据不可用。 |
| 显式研究过滤 | `RegimeAdaptiveBacktestEngine.run(..., allow_unavailable_symbols=True)` 可在适用分支过滤没有可观察本地数据的标的；这不是普通 CLI 的默认值，也不证明剩余股票的全部指标已就绪。 |
| 默认自适应回放 | `allow_unavailable_symbols=False`；`auto/replay` 发现请求股票缺少可观察数据时抛错，不静默缩小股票池。随后真实回放仍执行其数据和映射校验。 |
| 模拟日扫 | 日历未知、必需交易或参考股票及指数缺少目标交易日、提供层陈旧等中止；预热 `NOT_READY`、风险状态身份不匹配等可输出受限结果并抑制买入，不能叫作完整正常信号。 |
| 压力测试 | 调度经济任务前检查交易池、固定参考篮子及两只指数的文件完整性；池外参考股仍不计入交易池或场景标的数。文件存在不替代随后读取器的数据校验。 |
| 真实账户建议 | 日历或固定指数无法核验时入口失败；所需候选、参考或持仓数据缺失、陈旧、证据不一致时按实际 `data_complete`、`valuation_complete` 与买入限制处理。可用持仓的防御建议可能保留，缺少估值的持仓标记 `DATA_ERROR`，不生成貌似可执行的新数量，也不把缺失持仓当作零持仓。 |

`regime/` 没有 2021 年股票历史，会限制较早窗口的成熟动量证据；这不等于现行所有弱市入口在整个 2022 年都必然空仓。晚上市股票保留真实上市边界，不补造上市前历史。

公共前复权历史可能在公司行动后重述。现存冻结证据保持原字节、清单及来源；日常运行数据独立更新，不因此成为新的正式基线。新的研究输入及验收须按有效合同建立独立身份，不能通过刷新冻结目录或黄金预期消除失败。
